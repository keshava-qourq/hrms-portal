<!-- sdlc:auto:start overview -->
HRMS portal is a two-app repository generated by the Quorq AI SDLC platform. `frontend/` is a Vite + React 19 SPA (React Router, Tailwind 4) whose screens run on seeded sample data. `backend/` is a FastAPI service using SQLAlchemy, with SQLite by default and Postgres via `DATABASE_URL`. The backend currently exposes only `GET /health`. The models are empty, and `routers/` is an empty package. The product goal (per the README) is an HR portal with role-based access for Employees, Managers, HR and Admins, covering employee, timesheet, leave and approval workflows. None of that is implemented in the backend yet. `docker-compose.yml` provides Postgres and Redis for local use.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js and npm (the README does not pin a version; React 19, Vite 6 and Vitest 2 need a current LTS)
- Python 3.12 (the backend Dockerfile uses python:3.12-slim)
- Docker with Compose (optional: only for the Postgres/Redis services in docker-compose.yml or for building the backend image)
- Playwright's Chromium browser (only for e2e tests; installed via an npm script)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd backend && python -m venv .venv && source .venv/bin/activate
2. pip install -r requirements.txt
3. cd ../frontend && npm install
4. (Optional) Start Postgres and Redis from the repo root: docker compose up -d db redis
5. (Optional) To use Postgres instead of the default SQLite file (./app.db), set DATABASE_URL before starting the backend. The compose credentials are app/app/app, and requirements.txt installs psycopg 3, so an example is postgresql+psycopg://app:app@localhost:5432/app
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one router per architecture component. Unimplemented endpoints return the typed StubResponse (status 'not_implemented') so the OpenAPI document stays complete.
- Backend: all models inherit Base from app/database.py. main.py imports app.models so the tables register before Base.metadata.create_all runs at startup. There are no migrations; the code comments say to replace this with Alembic.
- Backend: handlers get a request-scoped SQLAlchemy session through the get_db dependency.
- Backend configuration is read from environment variables in code: DATABASE_URL (default sqlite:///./app.db) and ALLOWED_ORIGINS (comma-separated; defaults to the Vite dev origins on port 5173).
- Backend linting and formatting use Ruff (ruff.toml).
- Frontend: the '@' import alias maps to frontend/src (vite.config.ts and tsconfig.json).
- Frontend: component tests live beside the components under src/ (**/*.test\|spec.ts[x]). Vitest runs with jsdom and globals. Playwright specs live in e2e/ and are excluded from Vitest.
- Frontend: screens render seeded sample data. src/lib/api.ts (apiFetch) is the seam for replacing that with real calls. It sends the session token, or VITE_API_SECRET_KEY if none, as a Bearer header, and uses VITE_API_BASE_URL (default http://localhost:8000).
- Frontend TypeScript is strict but with noImplicitAny and strictNullChecks turned off. Formatting uses Prettier and linting uses ESLint.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` cannot import `app`. | Run it from the backend/ directory, where pytest.ini sets pythonpath = . and testpaths = tests. |
| Browser calls to the API fail with CORS errors. | The backend only allows http://localhost:5173 and http://127.0.0.1:5173 by default. If the frontend runs on another origin, set ALLOWED_ORIGINS (comma-separated) before starting uvicorn. |
| `docker compose up` fails because port 6379 is already allocated. | The `redis-queue` and `redis` services in docker-compose.yml both publish host port 6379. Start only one (for example `docker compose up -d db redis`) or change one of the host port mappings. |
| Playwright e2e fails to start the backend (e.g. '.venv/bin/python: not found'). | The config runs `cd ../backend && .venv/bin/python -m uvicorn ...`. Create backend/.venv and install requirements.txt into it first, or set E2E_BASE_URL to test an already running deployment. |
| `npm run build` succeeds but `npm run typecheck` reports errors. | This is expected: the build does not typecheck, and generated screens may have untyped state (such as `useState({})`). Fix the reported types before treating the codebase as maintained. |
| Frontend build or dev server cannot resolve `@/App`, or the screens listed in the README are missing. | main.tsx imports `@/App`, and the README describes src/App.tsx and src/screens/, but neither appears in the provided file tree. Confirm they exist in your checkout; otherwise the app cannot start. |
| Data is lost between runs or the schema does not match the models. | The backend defaults to a local SQLite file (./app.db) and creates tables from the models at startup, with no migrations. Set DATABASE_URL for a persistent database and add Alembic before storing data you need to keep. |
<!-- sdlc:auto:end troubleshooting -->
